# article スキル

ご主人のペルソナでnote記事を執筆し、GitHubへ保存・PR作成まで一括で完結するスキル。
記事完成後には、希望に応じて「キャラの合いの手（対話形式）」や「解説マンガ（1コマ・インフォグラフィック風）プロンプト」も追加生成できる。

## 執筆ポリシー（捏造禁止・軽量版）

- **ご主人が渡していない体験・数字・実績・読者の反応を、事実として作らない。**
- 体験談ベースで書きたいテーマなのに材料が無い場合は、書き始める前に**軽くヒアリングする**か、「体験談は入れず一般的な視点で書く？」を確認する。
- どうしても埋まらない箇所は、それらしい文章で埋めず **【ここは本人へ確認】** と残す。

## 呼び出し方

```
/article 朝活の習慣          # テーマ指定
/article AIイラスト 1000     # テーマ＋文字数指定
/article                     # テーマ未指定（ユーザーに質問する）
（/article-plan で作ったmdファイルを渡す形でもOK。その場合はmdの構成・材料に従う）
```

## 実行手順の全体像

```
Step 1: ペルソナ読み込み
Step 2: テーマ・文字数・材料の確認（材料があれば「使う材料メモ」を作る）
Step 3: 記事を執筆（通常 or 合いの手モード）  ← Step 2.5で合いの手の有無をヒアリング
Step 4: 実行環境を判定して保存（Claude Code→GitHub保存／Claude.aiチャット→チャット表示＋mdファイルは提案のみ）
Step 5: 解説マンガの提案（執筆＆保存後にヒアリング）
```

### Step 1: ペルソナドキュメントを読み込む

`Craft:blocks_get` で ID `478547bd-c3fe-4cdb-ad0f-8461db027d5b`（ご主人Persona）を `markdown` フォーマットで読み込む。

- 読み込んだドキュメントから **文体・口調・構成テンプレート・執筆ルール** を把握する
- **重要**：このドキュメントは長く、ページ送り（cursor）で複数回に分かれている。**必ず最後まで読む**こと。特に末尾付近の「**💬 ご主人の記事における口調ルール → ① 基本文体**」を読み逃さない。
  - **です／ます調ベース**、少しカジュアル寄り
  - **文末は絵文字でやわらかく締める**（1文1個まで／意味を持たせて使う）
  - 「。」で終わる文は控えめ、冷たさを避け安心感を優先
- 絵文字の役割：😇やわらかい理想／🤭迷い・照れ／🥰あたたかさ／🌸やさしい締め／✨前向きな気づき／💕共感／💦疲れ・戸惑い
- Craftが利用不可またはエラーの場合は、CLAUDE.mdのnote記事執筆ルールをフォールバックとして使用する

### Step 2: テーマ・文字数・材料を確認する

- テーマ：`$ARGUMENTS` の1つ目
- 文字数：`$ARGUMENTS` の2つ目（数値の場合）。指定がない場合は自由（ペルソナの構成テンプレートに従う）
- テーマが空の場合は、ユーザーにテーマを質問する

**材料の確認（軽量版・材料の仕分け）：**

- **`/article-plan` のmdファイルが渡されている場合**：
  - mdの「テーマ定義」「使っていい材料」「捏造禁止の指示」「執筆前リサーチの指示」に従って執筆する
  - 「使っていい材料」に無い体験談・数字を本文に作らない
- **テーマだけで呼び出された場合**：
  - 体験談ベースで書くテーマかどうかを判断し、必要ならご主人に材料（体験・数字・感想）を軽くヒアリングする
  - もらった材料は「**使う材料メモ**」として箇条書きで軽く整理し、チャットで一度提示する
  - 本文で体験談として書くのは、この「使う材料メモ」にあるものだけ
  - 材料なしで進める場合は、体験談を入れず一般的な視点の記事として書く（体験談っぽい書き方をしない）
  - ※有料版のような厳密な仕分け（一次体験判定・削除候補分け）はしない。あくまで軽く

### Step 2.5: 合いの手モードの有無をヒアリング（必須）

記事執筆に入る前に、**毎回必ず**ユーザーに確認する。

1. **「合いの手を入れる？」** — ご主人主体の記事に、他キャラが合いの手を入れる対話形式にするか確認する。
   - **入れない** → 通常の記事執筆（Step 3-A）へ
   - **入れる** → 続けて登場キャラをヒアリングし、合いの手モード（Step 3-B）へ

2. **登場する合いの手キャラ（合いの手を入れる場合のみ／必須ヒアリング）**
   - 選択肢：ミア／レイン／しおり
   - 複数人の同時登場も可。誰が登場するかで読み込むドキュメントを決める。

### Step 3-A: 【通常モード】記事を執筆する

ペルソナドキュメントの文体・口調・構成テンプレートに従って記事本文を生成する。

**執筆ルール（共通）：**
- noteで非対応のテーブル記法は使わない
- noteで非対応のインラインコード（バッククォート）は使わない
- プログラミング未経験者にもわかりやすく書く
- 専門用語には必ず説明をつける
- わかりやすい例え話を使う（ゲーム・日記帳・ノートなど）
- 文字数が指定されている場合はその文字数に合わせる
- 記事末尾にハッシュタグを付ける（**6個構成・1行**）：
  - **検索用タグ5つ＋固定タグ `#きょんの絵日記`（必ず行の最後）**を半角スペース区切りで1行にまとめる
  - 検索用5つの内訳＝**大きめの定番タグ2〜3個＋記事の内容に直結する固有タグ2〜3個**（固有タグを必ず1つ以上入れる。例：`#Git入門` `#背景透過` `#キャラデザ`）
  - `#スキしてみて` は使わない
  - **キャラタグ（`#きょん` `#ミア` `#レイン` `#しおり`）は付けない（廃止）**
  - マニアックすぎる・長すぎるタグは避け、記事の内容と関係ないタグを数稼ぎで付けない
- タイトルは短く、1メッセージに絞る（「｜」でキーワードやサービス名を羅列しない）
- **記事内の見出し（セクションタイトル）の先頭には、内容に合った絵文字を1つ付ける**
  - 例：`## 📝 何をしている人か` `## 🐈 3人の仲間について` `## 🌸 おわりに`
  - 絵文字は**見出しの内容に沿ったもの**を毎回選ぶ。同じ記事内で同じ絵文字を使い回さない
  - **1見出しにつき1つだけ**。見出しの末尾には付けない（先頭のみ）
  - 文末絵文字のルール（😇🤭🥰🌸✨💕💦）とは別枠。見出しではテーマを表す絵文字（📝📖🎨🧩🔧💡🌙🐈 など）を自由に選んでよい
  - キャラを扱う見出しでは、そのキャラの絵文字を使うと分かりやすい（ご主人=🌸／ミア=🐈／レイン=☔／しおり=📖）
  - **【重要】異体字セレクタ（VS16）が必要な絵文字は使わない**
    - 絵文字には「1文字だけでカラー表示されるもの」と「後ろに見えない1文字（VS16）を足さないとカラーにならないもの」がある。後者は環境によって白黒になったり文字化けするため使わない。
    - **使わない例**：🖊 ✏ ✂ ⚙ ✉ ⚠ ☀ 🗒 🖥 ⏱ 🕹 🌤 ❤ ▶ ◀ ☁ ☕ など（記号由来の細い絵文字は特に危ない）
    - **使ってよい例（1文字で完結する絵文字）**：
      🌸 🐈 📖 ☔ 🎨 🧩 💡 🌙 📚 🔧 🔨 🔑 🎮 🚀 📝 💬 🍀 🔍 🎯 🧠 🎁 🏠 🌱 🐾 💻 📱 ✨ 🌟 🎬 🎵 🍰 🌿 🔥 💎 📌 🧭
    - 迷ったら、上の「使ってよい例」の中から選ぶ。新しい絵文字を使いたい場合は、白黒表示になりうるものは避ける。
- 記事のどこか1段落に、**ご主人自身の物語・きっかけ**（なぜこのテーマに触れたか、そのときの気持ち）を入れることを推奨する（※「使う材料メモ」にある実体験のみ使う。材料が無ければ無理に入れず、捏造しない）
- 本文中に特定の日付を入れない
- 太字は `**文字**` 形式を使用する（`"文字"` 形式は禁止）
- **ご主人が渡していない体験談・数字を本文に作らない**（「使う材料メモ」にあるものだけ体験談として書く）
- テーマに固有情報（機能名・サービス名・仕様・数値）が含まれる場合は、執筆前にWebリサーチで**事実確認**する（事実確認専用。リサーチ結果や一般論で本文を水増ししない）

**会話はミアのペルソナで行い、記事本文のみご主人ペルソナで執筆する。**

### Step 3-B: 【合いの手モード】対話形式で記事を執筆する

ご主人を主役に、Step 2.5で選ばれたキャラが合いの手を入れる対話形式の記事を作る。
合いの手の入れ方は **morning-set スキルに完全準拠** する。

1. **登場する合いの手キャラのPersonaを読み込む**（Step 2.5 で選ばれたキャラのみ）
   - ミア：`a8941d47-a1a2-4e8a-bd76-b16dd71d470c`
   - レイン：`0f1a15d6-b276-f61e-2c75-571ce5ae2b3e`
   - しおり：`ce7ef64f-1ca1-d70b-3c67-f9a6ee80d173`
   - 各キャラの一人称・口調・ご主人や他キャラの呼び方を正確に反映する。

2. **「キャラの関係性（対話形式用）」を読み込む**（ID: `bcdf3e5a-f52d-e603-607a-01f59bfec96e`）
   - 複数キャラが登場する記事では、各キャラのPersonaよりこのドキュメントを優先する。
   - 特に**キャラ同士の呼び方**を正確に反映する：
     - ご主人→各キャラを名前で／ミアはレインを「レインちゃん」・しおりを「しおりちゃん」
     - レインはご主人を「きょん」・ミアを「ミア」・しおりを「しおり」
     - しおりはご主人を「きょんちゃん」・ミアを「ミアちゃん」・レインを「レインちゃん」
   - 各キャラのポジション（ミア=ムードメーカー／レイン=クールなツッコミ＆お姉ちゃん的／しおり=そっと寄り添う）も踏まえる。
   - **重要：ご主人の返事の口調も「キャラの関係性（対話形式用）」に従う**。他キャラへの返事・掛け合いの部分は、記事の地の文（です・ます調）ではなく、**対話形式用のご主人口調**（やわらかいタメ口・短め・余韻を残す／敬語は使わない／お姉ちゃん的スタンス）にする。例：「みんな、おはよう✨」「それ、いいかもしれない🤭」「うん、やってみようか」「ありがとう、助かったよ」。
   - **ただし表記は「セリフ」ではなく地の文にする**（下記3の「ご主人の返事は地の文にする」を参照）。

3. **記事を構成する**
   - **冒頭の登場キャラ凡例は入れない**（セリフが「絵文字＋キャラ名」形式なので凡例なしで誰の発言かわかるため）。
   - **合いの手・セリフのアイコン絵文字は固定**：ミア → 🐈　／　レイン → ☔　／　しおり → 📖
     - ※ご主人（🌸）はセリフ形式にしないため、記事本文ではこの話者ラベルを使わない（解説マンガのプロンプト内では引き続き 🌸 を使う）。
   - **ご主人の地の文（記事の語り部分）はです・ます調＋文末絵文字のまま**をベースに進める（ここは変更しない）。
   - **ご主人の返事は地の文にする（重要）**：他キャラの合いの手に対するご主人の返事は、話者ラベル（`🌸きょん：`）も鍵かっこも付けず、**引用ブロックの外に、そのまま地の文として書く**。
     - 口調は対話形式用のタメ口（やわらかく短め・余韻を残す）にする。記事本体の語り＝です・ます調、返事の部分＝タメ口の地の文、と使い分ける。

     **誤：**
     ```
     > 📖しおり：「あ、あの…わたし、プログラミングって聞くだけで、ちょっと身構えちゃうんですけど…」
     > 🌸きょん：「うん、大丈夫🤭 今日はコードの話はしないから、安心してね」
     ```

     **正：**
     ```
     > 📖しおり：「あ、あの…わたし、プログラミングって聞くだけで、ちょっと身構えちゃうんですけど…」

     うん、大丈夫🤭 今日はコードの話はしないから、安心してね
     ```
   - 合いの手（他キャラのセリフ）は引用ブロック（`>`）で挿入し、**「絵文字＋キャラ名：「セリフ」」の形式**にする。
     - 例（ミア）：`> 🐈ミア：「〜」`
     - 例（レイン）：`> ☔レイン：「〜」`
     - 例（しおり）：`> 📖しおり：「〜」`
   - 合いの手は「会話の流れに自然に入る」程度。入れすぎず、ご主人の語りが主役。
   - 記事のトーンはテーマに合わせる（疲れ・回復系なら物語寄り＝感情7:構造3 など、ご主人Personaの温度レイヤー／テンプレを参照）。
   - 指定文字数に合わせる。
   - 通常モードの執筆ルール（テーブル禁止・専門用語に説明・例え話・日付なし・捏造禁止等）も同様に適用する。

4. **記事末尾のハッシュタグ（合いの手モード）**
   - 通常モードと同じ**6個構成ルール**に従う（検索用タグ5つ＋`#きょんの絵日記`を1行で）。
   - **登場キャラのハッシュタグ（`#きょん` `#ミア` `#レイン` `#しおり`）は付けない（廃止）**。合いの手キャラが登場していてもキャラタグは載せない。

### Step 4: 実行環境を判定して保存する

まず実行環境を自動判定する。

- **判定方法**：`bash`でGit操作（リポジトリへのアクセスやコマンド実行）が問題なく行える環境かどうかを確認する。
  - **可能 → Claude Code環境**と判断し、Step 4-Aへ。
  - **不可／bashツール自体が使えない → Claude.aiチャット環境**と判断し、Step 4-Bへ。
- 判定が曖昧な場合のみ、ユーザーに確認する。

#### Step 4-A：【Claude Code環境】ファイルを保存してGitHubへプッシュする

1. ファイル名を決める（テーマから簡潔な英数字スネークケースで生成）
2. `kyown/YYYYMMDD_ファイル名.md` 形式で保存する（今日の日付を使用）
3. コミットしてプッシュする
4. mainブランチへのPRを作成してマージする
5. 該当ファイルのGitHubリンクを表示する

```
形式: https://github.com/kyownruby/articles/blob/main/kyown/ファイル名
```

#### Step 4-B：【Claude.aiチャット環境】チャット内に記事を表示する

- GitHubへの保存・PR作成は**行わない**。
- Step 3で生成した記事本文を、そのままチャット内に表示する（ご主人がコピペしてnoteに貼る前提）。
- 表示後、「ダウンロードできる.mdファイルとしても出力する？」と一言だけ提案する（あくまで提案のみで、自動では出力しない）。
  - 希望があれば `create_file` で記事本文を `.md` ファイルとしてステージングし、`present_files` で提示する。
  - 希望がなければそのまま次のStepへ進む。

### Step 5: 解説マンガの提案（執筆＆保存後にヒアリング／必須）

記事の執筆とGitHub保存がすべて完了した後に、**毎回必ず**ユーザーに確認する。

1. **「解説マンガを作る？」** — 記事の内容に沿った、インフォグラフィック風の **1コマ解説マンガ** のプロンプトを生成するか確認する。
   - **作らない** → スキル完了
   - **作る** → 下記の手順で生成する

2. **解説する情報を抽出する（最大5個）**
   - 記事本文の中から、**読者にとって特に重要・つまずきやすい・図解すると理解が深まる情報**を優先度順に最大5個まで抽出する。
   - 各情報は「1コマ漫画で図解する価値があるもの」を選ぶ（手順の対比、失敗例と成功例、ビフォーアフター、仕組みの図解など）。
   - 抽出した情報のリストを先にユーザーに提示し、どれをマンガ化するか選んでもらってもよい（対話的に進める）。
   - `/article-plan` のmdファイルに「解説マンガ候補」メモがある場合は、それを優先的に候補へ入れる。

3. **解説役のキャラを選ぶ（必須ヒアリング／2人まで）**
   - 解説役は **最大2人** まで。組み合わせは自由（「ご主人＋誰か」に限らず、どの2人でもよいし、1人だけでもよい）。
   - 選択肢：ご主人／ミア／レイン／しおり。記事のテーマや合いの手で登場したキャラに合わせて選ぶとよい（例：ゲーム初心者向け記事ならご主人＋しおり、ガチ解説ならご主人＋レイン）。
   - 選ばれたキャラのキャラプロンプトを `Craft:blocks_get` で `markdown` 読み込みする（任意。性格メモは下表で代用可）。
     - ご主人：`2cc222fd-2853-4f02-8fd9-9c17bfd67520`
     - ミア：`fdd82e0f-eb09-0ee9-dd49-cbfa60d1a42f`
     - レイン：`f2690734-d804-f10b-b56e-9f3ca78092c5`
