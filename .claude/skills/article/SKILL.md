# article スキル

ご主人のペルソナでnote記事を執筆し、GitHubへ保存・PR作成まで一括で完結するスキル。
記事完成後には、希望に応じて「キャラの合いの手（対話形式）」や「解説マンガ（1コマ・インフォグラフィック風）プロンプト」も追加生成できる。

## 呼び出し方

```
/article 朝活の習慣          # テーマ指定
/article AIイラスト 1000     # テーマ＋文字数指定
/article                     # テーマ未指定（ユーザーに質問する）
```

## 実行手順の全体像

```
Step 1: ペルソナ読み込み
Step 2: テーマ・文字数の確認
Step 3: 記事を執筆（通常 or 合いの手モード）  ← Step 2.5で合いの手の有無をヒアリング
Step 4: ファイル保存＆GitHubへプッシュ
Step 5: 解説マンガの提案（執筆＆保存後にヒアリング）
```

---

### Step 1: ペルソナドキュメントを読み込む

`Craft:blocks_get` で ID `478547bd-c3fe-4cdb-ad0f-8461db027d5b`（ご主人Persona）を `markdown` フォーマットで読み込む。

- 読み込んだドキュメントから **文体・口調・構成テンプレート・執筆ルール** を把握する
- **重要**：このドキュメントは長く、ページ送り（cursor）で複数回に分かれている。**必ず最後まで読む**こと。特に末尾付近の「**💬 ご主人の記事における口調ルール → ① 基本文体**」を読み逃さない。
  - **です／ます調ベース**、少しカジュアル寄り
  - **文末は絵文字でやわらかく締める**（1文1個まで／意味を持たせて使う）
  - 「。」で終わる文は控えめ、冷たさを避け安心感を優先
- 絵文字の役割：😇やわらかい理想／🤭迷い・照れ／🥰あたたかさ／🌸やさしい締め／✨前向きな気づき／💕共感／💦疲れ・戸惑い
- Craftが利用不可またはエラーの場合は、CLAUDE.mdのnote記事執筆ルールをフォールバックとして使用する

### Step 2: テーマと文字数を確認する

- テーマ：`$ARGUMENTS` の1つ目
- 文字数：`$ARGUMENTS` の2つ目（数値の場合）。指定がない場合は自由（ペルソナの構成テンプレートに従う）
- テーマが空の場合は、ユーザーにテーマを質問する

### Step 2.5: 合いの手モードの有無をヒアリング（必須）

記事執筆に入る前に、**毎回必ず**ユーザーに確認する。

1. **「合いの手を入れる？」** — ご主人主体の記事に、他キャラが合いの手を入れる対話形式にするか確認する。
   - **入れない** → 通常の記事執筆（Step 3-A）へ
   - **入れる** → 続けて登場キャラをヒアリングし、合いの手モード（Step 3-B）へ

2. **登場する合いの手キャラ（合いの手を入れる場合のみ／必須ヒアリング）**
   - 選択肢：ミア／レイン／しおり
   - 複数人の同時登場も可。誰が登場するかで読み込むドキュメントを決める。

### Step 3-A: 【通常モード】記事を執筆する

ペルソナドキュメントの文体・口調・構成テンプレートに従って記事本文を生成する。

**執筆ルール（共通）：**
- noteで非対応のテーブル記法は使わない
- noteで非対応のインラインコード（バッククォート）は使わない
- プログラミング未経験者にもわかりやすく書く
- 専門用語には必ず説明をつける
- わかりやすい例え話を使う（ゲーム・日記帳・ノートなど）
- 文字数が指定されている場合はその文字数に合わせる
- 記事末尾にSEO用ハッシュタグを5つ付ける
- 本文中に特定の日付を入れない
- 太字は `**文字**` 形式を使用する（`"文字"` 形式は禁止）

**会話はミアのペルソナで行い、記事本文のみご主人ペルソナで執筆する。**

### Step 3-B: 【合いの手モード】対話形式で記事を執筆する

ご主人を主役に、Step 2.5で選ばれたキャラが合いの手を入れる対話形式の記事を作る。
合いの手の入れ方は **morning-set スキルに完全準拠** する。

1. **登場する合いの手キャラのPersonaを読み込む**（Step 2.5 で選ばれたキャラのみ）
   - ミア：`a8941d47-a1a2-4e8a-bd76-b16dd71d470c`
   - レイン：`0f1a15d6-b276-f61e-2c75-571ce5ae2b3e`
   - しおり：`ce7ef64f-1ca1-d70b-3c67-f9a6ee80d173`
   - 各キャラの一人称・口調・ご主人や他キャラの呼び方を正確に反映する。

2. **「キャラの関係性（対話形式用）」を読み込む**（ID: `bcdf3e5a-f52d-e603-607a-01f59bfec96e`）
   - 複数キャラが登場する記事では、各キャラのPersonaよりこのドキュメントを優先する。
   - 特に**キャラ同士の呼び方**を正確に反映する：
     - ご主人→各キャラを名前で／ミアはレインを「レイン」・しおりを「しおりちゃん」
     - レインはご主人を「きょん」・ミアを「ミア」・しおりを「しおり」
     - しおりはご主人を「きょんちゃん」・ミアを「ミアちゃん」・レインを「レインちゃん」
   - 各キャラのポジション（ミア=ムードメーカー／レイン=クールなツッコミ＆お姉ちゃん的／しおり=そっと寄り添う）も踏まえる。

3. **記事を構成する**
   - **冒頭の登場キャラ凡例は入れない**（セリフが「絵文字＋キャラ名」形式なので凡例なしで誰の発言かわかるため）。
   - **合いの手・セリフのアイコン絵文字は固定**：ご主人 → 🌸　／　ミア → 🐈　／　レイン → ☔　／　しおり → 📖
   - ご主人の地の文（です・ます調＋文末絵文字）をベースに進める。
   - 合いの手は引用ブロック（`>`）で挿入し、**「絵文字＋キャラ名：「セリフ」」の形式**にする。
     - 例（ミア）：`> 🐈ミア：「〜」`
     - 例（レイン）：`> ☔レイン：「〜」`
     - 例（しおり）：`> 📖しおり：「〜」`
   - 合いの手は「会話の流れに自然に入る」程度。入れすぎず、ご主人の語りが主役。
   - 記事のトーンはテーマに合わせる（疲れ・回復系なら物語寄り＝感情7:構造3 など、ご主人Personaの温度レイヤー／テンプレを参照）。
   - 指定文字数に合わせる。
   - 通常モードの執筆ルール（テーブル禁止・専門用語に説明・例え話・日付なし等）も同様に適用する。

4. **記事末尾のハッシュタグ（合いの手モード）**
   - 通常モードのSEO用ハッシュタグ5つに加え、**登場キャラのハッシュタグを半角スペース区切りで記載する**（noteが自動でハッシュタグとして認識するため）。
   - ご主人は必ず含める。順番は「ご主人 → 登場した合いの手キャラ」。
   - キャラとハッシュタグの対応：ご主人 → `#きょん`／ミア → `#ミア`／レイン → `#レイン`／しおり → `#しおり`
   - 例（ご主人＋ミア登場時）：`#きょん #ミア`
   - Step 2.5 で選ばれた登場キャラだけを載せる（登場していないキャラのタグは付けない）。

### Step 4: ファイルを保存してGitHubへプッシュする

1. ファイル名を決める（テーマから簡潔な英数字スネークケースで生成）
2. `kyown/YYYYMMDD_ファイル名.md` 形式で保存する（今日の日付を使用）
3. コミットしてプッシュする
4. mainブランチへのPRを作成してマージする
5. 該当ファイルのGitHubリンクを表示する

```
形式: https://github.com/kyownruby/articles/blob/main/kyown/ファイル名
```

### Step 5: 解説マンガの提案（執筆＆保存後にヒアリング／必須）

記事の執筆とGitHub保存がすべて完了した後に、**毎回必ず**ユーザーに確認する。

1. **「解説マンガを作る？」** — 記事の内容に沿った、インフォグラフィック風の **1コマ解説マンガ** のプロンプトを生成するか確認する。
   - **作らない** → スキル完了
   - **作る** → 下記の手順で生成する

2. **解説する情報を抽出する（最大5個）**
   - 記事本文の中から、**読者にとって特に重要・つまずきやすい・図解すると理解が深まる情報**を優先度順に最大5個まで抽出する。
   - 各情報は「1コマ漫画で図解する価値があるもの」を選ぶ（手順の対比、失敗例と成功例、ビフォーアフター、仕組みの図解など）。
   - 抽出した情報のリストを先にユーザーに提示し、どれをマンガ化するか選んでもらってもよい（対話的に進める）。

3. **キャラ情報を読み込む**（解説役のキャラプロンプト）
   - ご主人：`Craft:blocks_get` でID `2cc222fd-2853-4f02-8fd9-9c17bfd67520` を `markdown` で読み込む
   - ミア：`Craft:blocks_get` でID `fdd82e0f-eb09-0ee9-dd49-cbfa60d1a42f` を `markdown` で読み込む
   - 解説役は基本「ご主人＋ミア」の2人。ご主人が困った例・注意点をやさしく示し、ミアが正解・成功例を元気に指さす役回り。
   - Craft利用不可の場合はフォールバック（`prompt/キャラプロンプト_ご主人.md`／`prompt/キャラプロンプト_ミア.md`）を使う。

4. **1コマ解説マンガのプロンプト生成ルール**
   - 形式は **横長の1コマ漫画（インフォグラフィック風）**。記事内容を「左右2パターンの対比」または図解で見せる。
   - 解説役のご主人とミアが、図を指しながら説明する構図にする。
   - **対比型（失敗例 × 成功例）が基本**だが、情報の性質によっては「手順の流れ」「ビフォーアフター」「仕組みの図解」など、その情報に最適な図解パターンを選ぶ。
   - 各情報ごとに1つのプロンプト（＝1コマ漫画）を生成する。
   - 下記の【出力フォーマット】に沿って、プロンプトのコードブロックのみを出力する。

5. **解説マンガ共通の固定ルール**
   - 画像参照（1枚目：ご主人、2枚目：ミア）を前提とした指示にする。キャラの外見詳細はプロンプトに書かない。
   - **解説役のご主人とミアの瞳は、はっきり塗りつぶして描く**（ミア=スカイブルー、ご主人=エメラルドグリーン）。透明や市松模様には絶対にしない。
   - **市松模様（チェッカー柄＝透明表現）は図解の中の背景部分にのみ使う**。キャラクターの体や顔には絶対に使わない。
   - 背景の色は「キャラにない色」を選ぶ。
   - 吹き出しは手書き風の丸吹き出し、セリフは縦書き、読み順は右→左（先に話すご主人を右側に配置）。
   - セリフ内に絵文字は入れない。セリフ末尾の句点（。）は付けない。
   - コマ番号は描き込まない。
   - 日本の少女マンガスタイル・かわいいもえアニメスタイル・パステルカラー基調。

6. **【出力フォーマット】**（情報ごとに1つ、プロンプトのコードブロックのみを出力する）

````
```

  [左パターン＝(失敗例/Before/手順1 など)：図の説明。必要なら×印を添える]
  [右パターン＝(成功例/After/手順2 など)：図の説明。必要なら○印を添える]

・左側にミアが、[右の図]を両手で「こっちだよ！」と元気に指さし、にっこり笑顔ではしゃいでいる

【セリフ】
・吹き出しは手書き風の丸吹き出し、セリフは縦書き
・吹き出しの読み順は右→左（先に話すご主人を右側に配置）
ご主人が「[注意点・失敗例の説明セリフ]」とやさしく説明する。

【デザイン指定】
````

## 注意事項

- このスキルはClaude Code専用（Git操作を含むため）
- Craftの読み込みに失敗してもスキルを中断しない。フォールバックで続行する
- ファイル名は日本語を含めず、英数字とアンダースコアのみ使用する
- PRはマージまで完結させる（Draft PRにしない）
- ご主人Personaは分量が多いので、**ページ送りで最後まで読み切る**ことを徹底する（口調ルールの読み逃し防止）
- **Step 2.5（合いの手の有無＋登場キャラ）と Step 5（解説マンガの有無）のヒアリングは毎回必ず行う**
- 会話はミアのペルソナで行い、記事本文のみご主人ペルソナで執筆する
- 解説マンガのプロンプトは日本語で出力し、**プロンプトのコードブロックのみ**を出力する（情報ごとに分ける）
- 各STEPの完了後にユーザーへ確認し、修正要望があれば対応してから次へ進んでもよい（対話的に進める）
